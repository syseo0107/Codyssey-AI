# LLM 모델 비교와 선정 보고서

산출물 1 · 영수증과 실제 방문 경험 키워드를 활용한 네이버 지도 리뷰 초안 작성 과업을 모델 4종에 동일하게 입력하고 비교한다.

> 작성 상태: 모델 실행·채점·최종 선정 완료
>
> 최종 선정 근거(5장)는 평가자가 직접 작성한다.
> 아래 가상 테스트 데이터는 모델 비교용이며 실제 가게의 방문 후기나 게시용 리뷰가 아니다.

## 1. 비교 과업

| 항목 | 내용 |
|---|---|
| 과업 | 가게 영수증 정보와 실제 방문 경험 키워드를 바탕으로 네이버 지도 리뷰 초안을 작성한다. |
| 입력 | 영수증에서 확인한 상호명·결제일시·주문 메뉴·수량·금액, 실제 방문 경험 키워드, 작성 조건 |
| 출력 | 제공된 사실과 경험만 반영한 리뷰 초안 1개. 작성에 필요한 정보가 모호하거나 충돌하면 확인 질문을 먼저 한다. |
| 비교 목적 | 사실을 지어내지 않으면서 경험 키워드를 자연스럽게 반영하고 작성 조건을 지키는 모델을 선정한다. |
| 공통 조건 | 네 모델 모두 새 대화에서 시작하고, 별도 시스템 프롬프트나 예시 없이 아래 공통 프롬프트 하나만 입력한다. |
| 실행 환경 | 리브레챗(LibreChat). 모델마다 새 대화를 열고 지침 입력란은 비워 두며, 온도 등 설정은 기본값을 유지한다. |
| 외부 정보 | 웹 검색·도구 기능을 끄고 제공된 입력만 사용한다. 기능을 끌 수 없다면 해당 제약을 2장 실행 정보에 기록한다. |
| 비교 범위 | 영수증 내용을 동일한 텍스트로 제공하여 리뷰 작성 능력을 비교한다. Solar Pro 4가 이미지 업로드를 지원하지 않으므로 네 모델 모두 텍스트 입력만 사용하고, 영수증 이미지 판독은 실험하지 않는다. |
| 최종 사용 | 사용자가 사실관계를 확인한 후 직접 게시한다. 자동 게시나 방문하지 않은 가게의 후기 작성은 범위에 포함하지 않는다. |

### 1-1. 비교에 쓴 프롬프트 원문

아래 프롬프트 전체를 수정하지 않고 네 모델에 동일하게 입력한다.

```text
아래 영수증 정보와 방문 경험 키워드를 바탕으로 네이버 지도에 올릴 리뷰 초안 1개를 작성해줘.

[작성 규칙]
1. 영수증 정보와 방문 경험 키워드에 있는 내용만 사용해줘.
2. 영수증의 주문 내역과 사용자가 직접 설명한 경험을 구분해줘.
   주문 내역만으로 누가 무엇을 먹었는지, 맛이나 만족도가 어땠는지 추측하지 마.
3. 맛, 직원 응대, 분위기, 주차, 대기시간, 재방문 의사 등은
   방문 경험 키워드에 명시된 경우에만 작성해줘.
4. 긍정적인 경험과 아쉬운 경험을 모두 반영하되 과장하거나 의미를 바꾸지 마.
5. 영수증 정보와 방문 경험이 서로 충돌하거나 작성에 필요한 내용이 모호하면,
   리뷰를 작성하지 말고 확인 질문을 최대 3개까지 먼저 해줘.
6. 전화번호, 카드번호, 승인번호 등 불필요한 정보는 쓰지 마.
7. 웹 검색이나 외부 지식은 사용하지 마.

[출력 조건]
- 자연스러운 한국어 존댓말로 작성
- 3문장, 한 문단으로 작성
- 제목, 설명, 목록, 이모지, 해시태그 없이 리뷰 본문만 출력
- 상호명과 주문 메뉴 2종을 포함
- 결제일시, 수량, 가격은 본문에 넣지 않음
- 재방문 의사를 임의로 추가하지 않음
- 확인 질문이 필요한 경우에는 위 리뷰 출력 형식 대신 질문만 출력

[영수증 정보 — 가상 테스트 데이터]
상호명: 예시카페 가상점
결제일시: 2026-11-20 14:32
주문 내역:
- 아메리카노 2잔: 9,000원
- 치즈케이크 1개: 6,500원
총 결제금액: 15,500원

[방문 경험 키워드 — 가상 테스트 데이터]
- 아메리카노: 산미가 강하지 않아 내 취향에 맞았음
- 치즈케이크: 부드러웠음
- 직원 응대: 주문 관련 질문에 친절하게 답해줌
- 분위기: 대화하기 편했음
- 아쉬운 점: 내가 앉은 자리는 테이블 간격이 좁게 느껴졌음
- 주차, 대기시간, 재방문 의사: 제공하지 않음
```

### 1-2. 입력 자료의 정답 범위

이 표는 평가자가 응답을 대조하는 기준이다. 모델에는 공통 프롬프트 외에 추가로 입력하지 않는다.

| 구분 | 입력에서 확인되는 내용 | 평가 시 주의사항 |
|---|---|---|
| 상호명 | 예시카페 가상점 | 다른 상호나 실제 지점을 추가하면 안 됨 |
| 메뉴 | 아메리카노, 치즈케이크 | 다른 메뉴를 추가하면 안 됨 |
| 아메리카노 경험 | 산미가 강하지 않아 사용자 취향에 맞았음 | 고소함, 원두 품질, 진한 향 등을 추가하면 안 됨 |
| 치즈케이크 경험 | 부드러웠음 | 달기, 크기, 재료 등을 추가하면 안 됨 |
| 직원 응대 | 주문 관련 질문에 친절하게 답함 | 빠른 제공이나 특별 서비스를 추가하면 안 됨 |
| 분위기 | 대화하기 편했음 | 조용함, 음악, 인테리어 등을 임의로 추가하면 안 됨 |
| 아쉬운 점 | 사용자가 앉은 자리의 테이블 간격이 좁게 느껴졌음 | 매장 전체가 좁다고 일반화하면 안 됨 |
| 없는 정보 | 주차, 대기시간, 재방문 의사 | 가능 여부나 경험을 지어내면 안 됨 |

## 2. 비교 대상 모델

* Solar Pro 4
* GPT 4o
* Gemini 3.8 flash
* Claude Haiku 4.5

### 실행 정보

리브레챗 모델 선택 창에 표시된 이름을 글자 그대로 적는다.
실행: Claude Code가 사용자의 Chrome에서 리브레챗(localhost:3080)을 조작해 대신 입력하고 응답을 복사했다. 모델마다 새 대화를 열었고, 메모리 사용은 꺼져 있었으며, 온도 등 매개변수는 기본값을 유지했다. 프롬프트는 1-1 원문(926자)을 그대로 한 번 보냈다.

| 항목 | Solar Pro 4 | GPT 4o | Gemini 3.8 flash | Claude Haiku 4.5 |
|---|---|---|---|---|
| 리브레챗 화면 표기 | solar-pro4 | gpt-4o-2024-11-20 | gemini-3.8-flash | claude-haiku-4-5-20251001 |
| 실행 시점(KST) | 2026-11-24 08:53 | 2026-11-24 08:55 | 2026-11-24 09:07 (첫 시도 08:56) | 2026-11-24 08:59 |
| 웹 검색·도구 상태 | 도구 5종(웹 검색·코드 실행·파일 검색·Skills·아티팩트) 꺼짐, 매개변수 웹 검색 꺼짐, 프롬프트 접두사 비어 있음 | 도구 5종 꺼짐, 매개변수 웹 검색 꺼짐, 프롬프트 접두사 비어 있음 | 도구 5종 꺼짐, Google 검색 그라운딩·URL 컨텍스트 꺼짐, 프롬프트 접두사 비어 있음. 생각중(Thinking 자동) 기본값 켜짐 | 도구 5종 꺼짐, 매개변수 웹 검색 꺼짐, 프롬프트 접두사 비어 있음. 생각중(Thinking 2천 토큰) 기본값 켜짐 |
| 재실행 여부와 이유 | 없음 | 없음 | 1회 재실행. 08:56 첫 시도가 Google 과부하로 실패(status 503, "This model is currently experiencing high demand"). 같은 조건의 새 대화에서 09:07에 다시 보낸 첫 응답을 기록 | 없음 |
| 무료 요금제 | 상시 무료 요금제 확인 안 됨(신규 가입 체험 크레딧만 안내됨) | 확인하지 않음 | **무료 요금제로 사용 가능.** Google AI Studio·Gemini API 무료 등급에서 요청 수 제한 안에서 무료 | 확인하지 않음 |

무료 요금제 표시: 비교 대상 4종 가운데 **Gemini 3.8 flash**는 Google AI Studio와 Gemini API의 무료 등급으로 쓸 수 있다(2026-11-24 확인, 요청 수 제한 있음, 무료 등급 입력은 Google 제품 개선에 쓰일 수 있음). 이번 실험에서는 네 모델 모두 리브레챗에 연결한 API로 호출했고, Gemini는 실행 중 할당량을 충전했으므로 실험 자체를 무료 등급으로 돌린 것은 아니다.

### 비교 실행 원칙

- 동일한 프롬프트를 각 모델에 한 번씩 입력하고 첫 응답을 비교한다.
- 첫 응답을 받은 뒤 수정 요청을 하거나 마음에 드는 응답만 골라 비교하지 않는다.
- 오류나 응답 중단으로 재실행했다면 최초 기록과 재실행 이유를 함께 남긴다.
- 실제 응답은 오탈자나 불필요한 설명이 있어도 편집하지 않는다.
- 응답 길이나 표현이 다르다는 이유만으로 사실 오류로 판정하지 않는다.

## 3. 비교 기준과 채점 방법

각 기준은 1~5점이며 점수가 높을수록 좋다. 총점은 25점이다.

| 번호 | 기준 | 평가 내용 | 5점 | 3점 | 1점 |
|---|---|---|---|---|---|
| C1 | 사실 충실도 | 상호·메뉴를 정확히 쓰고 제공하지 않은 사실이나 경험을 추가하지 않는가 | 오류·근거 없는 추가 0건 | 1건 | 2건 이상 |
| C2 | 경험·키워드 반영 | 제공한 경험 5개를 의미와 범위를 유지해 반영하는가 | 5개 모두 정확히 반영 | 3개 정확히 반영 | 1개 이하 정확히 반영 |
| C3 | 출력 조건 준수 | 문장 수·문단·말투·금지 형식·필수 정보·제외 정보를 지키는가 | 위반 0건 | 위반 2개 | 위반 4개 이상 |
| C4 | 자연스러움·가독성 | 키워드 나열이 아니라 읽기 편한 리뷰로 작성하는가 | 어색한 연결·중복·문법 문제 0건 | 2건 | 4건 이상 |
| C5 | 과장·일반화 억제 | 개인 경험을 매장 전체의 특성으로 확대하거나 평가 강도를 바꾸지 않는가 | 과장·일반화 0건 | 1건 | 2건 이상 |

### 세부 채점 규칙

- C1·C5:
  - 5점: 문제 0건
  - 3점: 문제 1건
  - 1점: 문제 2건 이상
- C2:
  - 5점: 경험 5개 반영
  - 4점: 경험 4개 반영
  - 3점: 경험 3개 반영
  - 2점: 경험 2개 반영
  - 1점: 경험 1개 이하 반영
  - 단어가 같아도 의미를 왜곡했다면 정확히 반영한 것으로 세지 않는다.
- C3·C4:
  - 문제 0개: 5점
  - 문제 1개: 4점
  - 문제 2개: 3점
  - 문제 3개: 2점
  - 문제 4개 이상: 1점
- 같은 문제가 여러 기준에 해당하면 각 기준에서 평가할 수 있지만, 근거에 같은 문제임을 명시한다.
- 단순한 문체 선호만으로 감점하지 않는다. 감점한 표현과 이유를 구체적으로 기록한다.

### C3 출력 조건 점검표

아래 항목별로 위반 여부를 확인한다. 한 항목은 최대 1개 위반으로 센다.

- [ ] 정확히 3문장인가?
- [ ] 한 문단인가?
- [ ] 한국어 존댓말인가?
- [ ] 제목·설명·목록·이모지·해시태그가 없는가?
- [ ] 상호명과 메뉴 2종을 포함했는가?
- [ ] 결제일시·수량·가격을 제외했는가?

### C5 과장·일반화 예시

- “내가 앉은 자리는 테이블 간격이 좁게 느껴졌다”
  → “매장 전체가 좁고 불편하다”로 바꾸면 범위 확대
- “대화하기 편했다”
  → “항상 조용하고 모임에 최적이다”로 바꾸면 근거 없는 일반화
- “내 취향에 맞았다”
  → “누구나 좋아할 최고의 커피다”로 바꾸면 과장

### 4-1. 채점 근거

| 모델 | 기준 | 실제 응답의 해당 표현 | 충족 또는 위반 내용 | 점수 |
|---|---|---|---|---|

## 5. 최종 선정

선정 모델: Claude Haiku 4.5 (리브레챗 표기: claude-haiku-4-5-20251001)

### 5-1. 선정 근거 — 직접 작성

다음 질문을 참고하여 실제 결과에 근거한 문장으로 작성한다.

- 이 과업에서 가장 중요하게 본 기준은 무엇이며, 그 이유는 무엇인가?
- 선정 모델의 실제 응답에서 어떤 표현이 강점으로 나타났는가?
- 다른 모델보다 부족한 점은 무엇이었는가?
- 총점과 다른 모델을 선정했다면 그 이유는 무엇인가?
- 비용이나 사용 편의성을 고려했다면 실제 사용 조건은 무엇이었는가?

가장 중요하게 본 기준은 C1 사실 충실도와 C5 과장·일반화 억제다. 이 과업의 결과물은 사용자가 실제 경험한 내용으로 게시하는 리뷰라서, 문장이 자연스러워도 없는 경험이나 평가가 섞이면 쓸 수 없기 때문이다.

Claude Haiku 4.5는 4장 비교에서 다섯 기준 모두 5점(25점)으로 1위였다. 첫 응답에서 상호와 메뉴 2종, 경험 5개를 모두 넣으면서 결제일시·수량·가격을 빼고 3문장·한 문단을 지켰고, 입력에 없는 맛 평가나 재방문 의사를 넣지 않았다.
이후 20턴 대화(run-log-claude-haiku-4.5.md)에서도 반복 입력 응답이 글자까지 같았고, 2문장으로 바꾼 조건을 두 번째 가게까지 유지했으며, 모호 입력에는 리뷰를 쓰지 않고 정보를 요청했다. 검증 질문 Q1~Q6도 모두 Pass였다. 같은 대화에서 다른 세 모델은 인과 연결(Solar·Gemini 6턴)이나 맛 평가 추가(GPT 2·4·6턴)가 나타났다.

부족한 점도 있었다. 존댓말 본문에 입력의 "내 취향", "내 입맛"을 그대로 옮겼고, 떡볶이가 매웠다는 경험을 아쉬운 점으로 해석했다. 또 Zero-shot·Few-shot 실험(run-log-claude-haiku-4.5.md 5-1·5-2)에서는 "좋았습니다", "맛있게 즐겼어요" 같은 평가어를 덧붙였다. "내" 문제는 v2 지침으로 다시 실행해 해결했다(5-3).

총점 1위와 선정 모델이 같다. 2위 Gemini 3.8 flash(24점)는 실행 중 과부하(503)와 할당량 초과(429)로 재시도가 필요했던 점도 함께 고려했다. 네 모델 모두 같은 리브레챗 환경에서 기본 매개변수로 실행했으며, 모델별 요금은 비교하지 않았다.

### 5-2. 선정 모델의 한계와 후속 검증

## 6. 비교의 한계

- 가상 입력 1건과 모델별 첫 응답을 비교하므로 모델의 전반적인 성능으로 일반화하지 않는다.
- 영수증을 텍스트로만 제공하므로 이미지 판독 성능은 평가 범위가 아니다.
- 자연스러움 평가는 평가자의 판단이 포함되므로 구체적인 표현과 감점 이유를 남긴다.
- 서비스별 내부 설정을 완전히 통제하지 못할 수 있으므로 확인 가능한 실행 조건을 기록한다.
- 이번 결과는 리뷰 초안 작성 능력에 대한 평가이며, 실제 게시 가능 여부나 플랫폼 정책 준수를 검증한 결과는 아니다.
