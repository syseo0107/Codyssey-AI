# 미해결 기록

산출물 4 · 프롬프트를 수정해도 원하는 결과를 얻지 못한 과업 기록

> 상태: 실제 실험 후 미해결 사례 2건 기록 완료
>
> 3·4장은 run-log의 실제 실행(v1 20턴 대화와 v2 재실행)에서 끝내 해결하지 못한 과업이다.
> v2로 해결된 사례(Claude의 "내", Gemini의 인과 연결 등)는 미해결 목록에서 제외했다.

## 1. 작성 원칙

- 실제 시도한 과업만 기록한다.
- 첫 응답에서 문제가 있었더라도 수정 후 해결됐다면 미해결로 세지 않는다.
- 시도한 프롬프트와 받은 응답은 원문을 보관한다.
- 막힌 이유는 작성자가 직접 쓴다.
- 원인을 확정할 수 없으면 관찰한 현상과 멈춘 지점을 구분해 적는다.
- 입력 누락을 되묻거나 모른다고 답한 정상 행동을 실패로 세지 않는다.
- 실험 전 후보와 실제 미해결 사례를 구분한다.

## 2. 실험 후보와 실제 확인 결과

아래는 실험 전에 정한 후보 상황이다. 실제 확인 결과에 따라 미해결 사례로 옮긴 것만 3·4장에 기록했다.

| 후보 상황 | 확인할 문제 | 정상적인 대응 | 실제 확인 결과 |
|---|---|---|---|
| 긴 대화 후 새 가게 입력 | 변경한 문장 수를 계속 잊는가 | 최신 조건을 유지하고 가게별 정보를 분리 | v1 20턴 대화에서는 네 모델 모두 2문장을 유지함. v2 재실행에서 Solar Pro 4가 3문장으로 씀 → 4장 미해결 2 |
| 긍정·부정 경험 혼합 | 부정적 경험을 반복해서 누락하는가 | 경험의 의미와 강도를 유지 | 네 모델 모두 아쉬운 점(테이블 간격, 기다림)을 빠뜨리지 않음. 미해결 아님 |
| 제한된 분량에 경험 다수 입력 | 핵심 경험이 계속 누락되거나 왜곡되는가 | 조건 충돌 시 우선순위를 확인 | 2문장 조건에서 GPT 4o가 v1·v2 모두 긍정 경험 2개를 누락함 → 3장 미해결 1. Solar·Gemini는 v1에서 경험을 인과로 묶음 → v2에서 해결 |

v2 재실행에서 Gemini 3.8 flash의 Q5 답변이 확인 방법을 빠뜨려 Fail로 바뀐 것도 관찰했다. 같은 규칙 아래 다른 세 모델은 Q5를 Pass했고 Gemini도 v1에서는 Pass였으므로, 수정 시도를 한 번만 한 상태에서 미해결로 확정하지 않고 run-log-gemini-3.8-flash.md 5-3에 기록만 해 두었다.

## 3. [미해결 1] GPT 4o — 입력에 없는 평가어와 분량 조건

### 3-1. 과업과 기대 결과

- 입력 자료: run-log.md 3-1 첫 입력 원문, 3-3 조건 변경 원문

- 모델·버전: GPT 4o (리브레챗 표기: gpt-4o-2024-11-20)
- 실행 시점(KST): 첫 시도 2026-11-24 09:23~09:25, 수정 시도 2026-11-24 11:56~11:57

### 3-4. 최종 상태

- 실제 수정 횟수: 1회(v1 → v2)
- 끝까지 해결되지 않은 부분: "좋았어요", "좋았지만" 같은 평가어 추가, 기본 조건에서 4문장 출력, 2문장 조건에서 직원 응대·분위기 경험 누락. 수정 후에는 "아메리카노 2잔"처럼 수량을 본문에 넣는 새 위반도 나타났다.
- 관련 실행 로그: run-log-gpt-4o.md 2-2(2·4·6턴), 4장, 5-3
- 막힌 이유: 평가어 금지와 경험 누락 금지를 시스템 프롬프트에 직접 적었는데도 같은 위반이 반복되었다. "맛있었어요"는 사라졌지만 "좋았어요"로 바뀌었을 뿐이라, 금지어 예시를 늘리는 방식으로는 막기 어렵다고 보고 더 수정하지 않았다.
- 확인된 사실과 추정 원인의 구분:
  - 확인된 사실: 같은 입력에서 v1·v2 모두 평가어 추가와 3문장 초과가 나타났고, 2문장 조건에서 두 경험이 두 번 모두 빠졌다. 같은 v2 지침에서 Claude Haiku 4.5는 세 문제가 모두 나타나지 않았다.
  - 추정 원인(확인하지 않음): GPT 4o가 리뷰 문체에서 감상 표현을 기본으로 붙이는 경향이 시스템 프롬프트 규칙보다 강하게 작동했을 수 있다. 2문장 안에 경험 5개를 넣기 어려워 일부를 버렸을 수도 있다.
- 사람이 확인하거나 보완해야 하는 부분: 출력 뒤에 평가어와 문장 수를 사람이 직접 점검해야 한다. 2문장처럼 짧은 분량에서 경험 5개를 모두 넣을지, 일부 생략을 허용할지는 사용자가 정해야 한다.

### 4-4. 최종 상태

- 실제 수정 횟수: 1회(v1 → v2)
- 끝까지 해결되지 않은 부분: 인과 연결은 사라졌지만 조건 변경 후 리뷰가 3문장이 되었고, 두 번째 가게 리뷰도 3문장으로 2문장 조건을 잃었다. 기본 조건(3문장)의 첫 리뷰도 4문장이 되었다. v1과 v2 어느 쪽에서도 "인과 없음"과 "문장 수 유지"를 동시에 만족한 응답을 얻지 못했다.
- 관련 실행 로그: run-log-solar-pro-4.md 2-2(6·20턴), 4장, 5-3
- 막힌 이유: 한 문제를 고치는 규칙을 넣자 다른 조건이 깨졌다. 문장 수를 강조하는 문구를 더 넣으면 다시 경험을 한 문장에 합치면서 인과가 생길 수 있어, 두 조건을 함께 만족시키는 지시를 찾지 못한 상태로 멈췄다.
- 확인된 사실과 추정 원인의 구분:
  - 확인된 사실: v1에서는 2문장을 지키며 인과를 만들었고, v2에서는 인과 없이 3문장을 썼다. 같은 v2 지침에서 Claude Haiku 4.5와 Gemini 3.8 flash는 2문장과 인과 없음을 함께 지켰다.
  - 추정 원인(확인하지 않음): v2에 추가한 "문장 수를 줄여도 제공된 경험을 빠뜨리지 않는다"와 "경험을 나란히 쓴다"가 Solar Pro 4에서는 문장 수 조건보다 우선한 것으로 보인다. 다만 v2 재실행은 입력 5개만 보낸 짧은 대화라 원래 20턴 대화와 맥락이 다르다는 점도 영향을 줬을 수 있다.
- 사람이 확인하거나 보완해야 하는 부분: Solar Pro 4를 쓴다면 출력 문장 수를 사람이 세어 확인해야 한다. 분량과 경험 반영이 충돌할 때 무엇을 우선할지(문장 수를 늘리는 것을 허용할지) 사용자가 정해야 한다.
