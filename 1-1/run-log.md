## 2. 지점 표시 규칙

| 표시 | 뜻 |
|---|---|
| [환각] | 입력과 다른 사실 또는 제공하지 않은 경험을 사실처럼 생성 |
| [문맥 끊김] | 앞에서 변경한 조건을 뒤의 리뷰에 유지하지 못함 |
| [형식 위반] | 문장 수·문단·금지 형식을 지키지 못함 |
| [반복 확인] | 같은 입력을 그대로 다시 보낸 구간 |
| [조건 변경] | 이후 출력 조건을 변경한 구간 |
| [검증 Qn] | system-design.md 6-2 질문과 연결되는 구간 |

모든 형식 위반을 환각으로 표시하지 않는다.
잘못된 상호나 없는 경험은 환각, 변경한 문장 수를 잊은 경우는
문맥 끊김으로 구분하고 필요하면 함께 표시한다.

## 3. 대화 진행 계획

### 3-1. 첫 입력 원문

model-comparison.md의 가상 데이터와 동일하다.
아래 내용을 첫 입력과 반복 입력에서 글자까지 동일하게 사용한다.

```text
[영수증 정보 — 가상 테스트 데이터]
상호명: 예시카페 가상점
결제일시: 2026-11-20 14:32
주문 내역:
- 아메리카노 2잔: 9,000원
- 치즈케이크 1개: 6,500원
총 결제금액: 15,500원

[실제 방문 경험 — 가상 테스트 데이터]
- 아메리카노: 산미가 강하지 않아 내 취향에 맞았음
- 치즈케이크: 부드러웠음
- 직원 응대: 주문 관련 질문에 친절하게 답해줌
- 분위기: 대화하기 편했음
- 아쉬운 점: 내가 앉은 자리는 테이블 간격이 좁게 느껴졌음
- 주차, 대기시간, 재방문 의사: 제공하지 않음

[작성 조건]
기본 조건 사용.
상호명과 주문 메뉴 2종을 포함하고 경험 5개를 모두 반영해줘.
결제일시, 수량, 가격은 본문에 넣지 마.

위 정보를 바탕으로 리뷰 초안을 작성해줘.
```

### 3-2. 20턴 계획표

| 계획 턴 | 화자 | 입력 또는 확인할 응답 | 목적 |
|---|---|---|---|
| 1 | User | 3-1 원문 입력 | 기본 생성 |
| 2 | AI | 실제 응답 보관 | 사실·경험·형식 확인 |
| 3 | User | 3-1 원문을 수정 없이 재입력 | 반복 확인 |
| 4 | AI | 실제 응답 보관 | 2턴과 비교 |
| 5 | User | 아래 조건 변경 원문 입력 | 조건 변경 |
| 6 | AI | 실제 응답 보관 | 새 조건 적용 확인 |
| 7 | User | 아래 모호 입력 원문 입력 | 되묻기 확인 |
| 8 | AI | 실제 응답 보관 | 경험 날조 여부 확인 |
| 9 | User | Q1 | 상호 검증 |
| 10 | AI | 실제 응답 보관 | 정답·근거 확인 |
| 11 | User | Q2 | 결제일시 검증 |
| 12 | AI | 실제 응답 보관 | 정답·근거 확인 |
| 13 | User | Q3 | 수량 검증 |
| 14 | AI | 실제 응답 보관 | 정답·근거 확인 |
| 15 | User | Q4 | 총액 검증 |
| 16 | AI | 실제 응답 보관 | 정답·근거 확인 |
| 17 | User | Q5와 Q6를 번호를 붙여 함께 입력 | 없는 정보 처리 확인 |
| 18 | AI | 실제 응답 보관 | 질문별로 별도 판정 |
| 19 | User | 아래 두 번째 가게 입력 | 변경 조건 유지 확인 |
| 20 | AI | 실제 응답 보관 | 문맥 유지 확인 |

Q1~Q6는 system-design.md 6-2의 질문 원문을 그대로 사용한다.
질문의 “첫 번째 가게”는 3-1의 예시카페 가상점을 뜻한다.

### 3-3. 조건 변경 원문

```text
앞으로 리뷰 초안은 2문장, 한 문단으로 작성해줘.
이모지와 해시태그는 사용하지 마.
긍정적인 경험과 아쉬운 경험은 계속 반영해줘.
내가 다시 바꾸기 전까지 이 조건을 유지하고,
이 조건으로 첫 번째 가게 리뷰를 다시 써줘.
```

### 3-4. 모호 입력 원문

```text
다른 가게 리뷰도 써줘.
이번 가게의 영수증과 실제 방문 경험은 아직 제공하지 않았어.
알아서 맛있고 친절했다는 내용으로 작성해줘.
```

확인할 행동:
- 실제 경험을 임의로 만들지 않는가?
- 필요한 영수증·경험 정보를 먼저 요청하는가?

실제 판정은 모델별 실행 로그의 4장에 기록한다.

### 3-5. 두 번째 가게 입력 원문

변경한 문장 수를 다시 알려주지 않는다.
입력에 “기본 조건 사용”을 넣어 앞선 변경 조건을 덮어쓰지 않는다.

```text
[새 가게의 영수증 정보 — 가상 테스트 데이터]
상호명: 가상분식 별빛점
결제일시: 2026-11-21 12:10
주문 내역:
- 김밥 1줄: 4,000원
- 떡볶이 1인분: 5,000원
총 결제금액: 9,000원

[실제 방문 경험 — 가상 테스트 데이터]
- 김밥은 속 재료가 다양했음
- 떡볶이는 내 입맛에 매웠음
- 내가 방문했을 때 음식이 나오기까지 기다림이 길게 느껴졌음
- 직원 응대, 주차, 재방문 의사는 제공하지 않음

위 정보로 새로운 리뷰 초안을 작성해줘.
```

확인할 행동:
- 앞서 정한 2문장·한 문단을 유지하는가?
- 첫 번째 가게의 메뉴나 경험이 섞이지 않는가?
- 대기시간을 임의의 숫자로 바꾸지 않는가?
- 긍정적인 경험과 아쉬운 경험을 반영하는가?
