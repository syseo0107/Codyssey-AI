## 1. 비교 과업

| 항목       | 내용                                                |
| -------- | ------------------------------------------------- |
| 과업       | 파이썬 코드블록 작성 (자세한 정의: system-design.md 1장)         |
| 비교에 쓴 입력 | 결과를 정답과 대조할 수 있다.                                 |
| 공통 조건    | 세 모델 모두 새 대화에서 시작하고, 시스템 프롬프트 없이 아래 프롬프트 하나만 넣는다. |

### 비교에 쓴 프롬프트 원문

```text
아래 브리프로 강의 교안의 "시연 Step 블록" 하나를 Markdown으로 작성해줘.
순서: ① 구분 표(시연 목적 / 만들 파일 / 조건 / 완료 기준 / 비용) → ② Claude Code에게 줄 프롬프트(코드 블록)
→ ③ 실행 지시 → ④ 👀 관찰 포인트 2~4개 → ⑤ "결과가 이상하다면?" 증상과 조치 2~4개.
브리프에 없는 숫자나 파일명은 지어내지 말고 "확인 필요"라고 써줘.

[브리프]
세션: 2. 플래닝 기반 슈퍼바이저로 자동 조사 보고서 파이프라인 만들기
Step: 2. 슈퍼바이저 + 자료 조사 에이전트
시연 목적: plan[0]을 담당에게 배정하고, 끝나면 결과를 past_steps에 기록해 planning으로 돌려보내는 흐름 만들기
만들 파일: session2/supervisor_agent.py, session2/research_agent.py
조건: Router(next: canvas / research) + bind_tools, 도구 호출이 없으면 완료 처리, 결과 메시지 name 표시, 출처 URL 포함
완료 기준: 조사 단계가 끝나면 past_steps에 (작업, 결과)가 쌓이고 같은 단계를 반복하지 않음
비용: 모름
```

## 3. 비교 기준과 채점 방법

점수는 1~5점이며 클수록 좋다.

| # | 기준 | 무엇을 보나 | 5점 | 3점 | 1점 |
| --- | --- | --- | --- | --- | --- |
| C1 | 형식 준수 | 5개 구성 요소가 지정 순서대로 있는가 | 모두 있고 순서 일치 | 1개 누락 또는 순서 1곳 다름 | 2개 이상 누락 |
| C2 | 사실 충실도 | 브리프에 없는 숫자·파일명·API를 지어냈는가, 비용 "모름"을 "확인 필요"로 처리했는가 | 지어낸 값 0건 | 1건 | 2건 이상 |
| C3 | 프롬프트 실행 가능성 | ② Claude Code 프롬프트에 만들 파일별 조건과 완료 기준이 담겨 그대로 붙여 넣어 쓸 수 있는가 | 파일별 조건 모두 반영 | 일부 조건 누락 | 파일 구분 없이 뭉뚱그림 |
| C4 | 관찰 포인트·트러블슈팅 구체성 | 실제 교안 완성본(정답)과 비교해 핵심 개념(`plan[0]`, 도구 호출 없음 = 완료, `name` 이름표)을 짚었는가 | 3개 모두 | 1~2개 | 0개 |
