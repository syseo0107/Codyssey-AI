# 미션 4 준비 정리: AI 기반 소셜 미디어 콘텐츠 자동 생성

> 정리 일시: 2026-11-25 · 자동화 도구: n8n

---

## 1. 미션 요약

- **과업:** 주제를 한 번 입력하면 플랫폼별 텍스트와 대표 이미지가 생성되고 노션에 자동 저장되는 워크플로우 구축
- **기능 요구사항 4가지**
  1. 입력·트리거: 폼 등으로 주제를 받고, 입력하면 워크플로우가 자동 실행
  2. 플랫폼별 텍스트: 최소 3개 플랫폼, 플랫폼마다 톤 조정
     - 인스타그램: 짧은 캡션 + 해시태그 10개 내외
     - 블로그: 500자 이상 본문 + 소제목 구조
     - X: 280자 이내 요약
  3. 이미지: 주제에 맞는 대표 이미지, 소셜 미디어에 쓸 수 있는 품질
  4. 결과 저장: 노션 등 협업 도구에 자동 저장, 플랫폼별로 구분
- **보너스:** 톤이 다른 2가지 버전(A/B) 생성 + 변수별로 효과적인 콘텐츠 결론 정리
- **금지:** 저작권 문제가 있는 콘텐츠 무단 게시, 타인 콘텐츠를 복사해 제출

### 산출물과 파일

| 산출물 | 파일 |
| --- | --- |
| 1. 자동화 워크플로우 | 워크플로우구조.png, 워크플로우설명.md (선택: 워크플로우내보내기.json) |
| 2. 플랫폼별 결과물 | 결과물/인스타그램.md·블로그.md·X_트위터.md, 대표이미지.png, 협업도구페이지.png, README.md에 노션 보기 링크 |
| 3. 프롬프트 템플릿 | 프롬프트템플릿.md (플랫폼별 설계, 초안 → 수정 → 최종 기록) |
| 4. 코랩 세션 리포트 | 코랩세션리포트.md (조원들과 함께 작성) |

- GitHub 웹에서 저장소를 만들어 업로드하고, 저장소 URL을 제출
- 키, 토큰, 계정 이메일은 값이 보이지 않게 가림
- 노션 페이지는 보기 권한으로 공유한 링크를 README.md에 적음

## 2. 진행 순서

1. **도구와 키 준비:** n8n, 텍스트 생성 API, 이미지 생성 API, 노션 연동 토큰
2. **노션 저장 구조 만들기:** 데이터베이스 + 프로젝트 개요·작업 과정 요약 페이지
3. **채팅에서 프롬프트 초안 시험:** 고치기 전 초안을 그대로 저장 (프롬프트템플릿.md의 "초안")
4. **n8n 워크플로우 연결**
5. **실행하고 고치기:** 주제 2~3개로 돌려 보며 프롬프트 수정, 수정할 때마다 무엇을 왜 바꿨는지 기록
6. **정리와 업로드:** 결과물 정리, 마스킹 확인, 여유 있으면 보너스 A/B
7. **코랩 세션과 제출:** 세션 → 리포트 작성 → 저장소 URL 제출

## 4. 워크플로우 노드 구성

> **실제 구현 (2026-11-28, 노드 21개, `tools/build-workflow.js`가 `워크플로우내보내기.json`을 만든다)**
>
> 1. **폼 입력 → 입력 정리:** 주제(필수), 보는 사람, 톤(친근/전문), 버전(A/B)을 받는다. 최종 프롬프트 4개로 요청 본문을 만든다.
> 2. **플랫폼 4줄 (인스타그램·블로그·X·이미지 프롬프트):** 생성(HTTP) → 검사(Code, `tools/check.js`와 같은 코드) → 완료?(If).
>    - 기준을 벗어나면 다시 생성하고, 최대 3번까지 시도한다.
>    - 처음 계획한 병렬·Merge 대신 순서대로 이어 붙였다. 재생성 루프와 시도 횟수 세기(`$runIndex`)가 단순해지기 때문이다.
> 3. **이미지:** Gemini 생성 → 노션 업로드 만들기 → 이미지 꺼내기 → 이미지 파일로 → 노션 업로드 보내기 (File Upload API 3단계)
> 4. **노션 행 만들기 → 노션 저장:** 플랫폼마다 행 1개씩 총 4행을 만든다.
>    - 대표 이미지 행에 파일을 첨부한다.
>    - 검사를 통과하지 못한 채 끝난 행은 본문 맨 위에 실패 사유를 적는다.
>
> 실제 노션 열 14개: 제목, 주제, 플랫폼, 본문, 해시태그, 이미지, 톤, 대상, 버전, 훅 유형, 글자 수, 검사 통과, 실행 ID, 생성 시각

처음 계획 (2026-11-25):

1. **폼 트리거 (On form submission):** 주제(필수), 톤(친근/전문), 대상(선택). 톤 칸은 보너스 A/B에도 사용
2. **텍스트 생성 노드 3개 (병렬):** 인스타그램, 블로그, X에 노드 하나씩. 출력은 JSON으로 받아 노션 열에 나눠 넣음
3. **Code 노드 검증:** 블로그 글자 수와 소제목, 해시태그 개수, X 글자 수를 셈. 기준을 벗어나면 If 노드로 재생성 (최대 2회)
4. **이미지 생성:** LLM이 이미지 프롬프트를 먼저 쓰고, 그 프롬프트로 이미지 생성
5. **Merge → 노션 저장:** 플랫폼마다 데이터베이스 행 1개, 플랫폼 열로 구분

**노션 데이터베이스 열 (안):** 주제, 플랫폼, 본문, 해시태그, 이미지, 버전(A/B), 훅 유형, 생성 시각

## 5. 막히기 쉬운 곳

- **X 글자 수:** 실제 X는 한글 1자를 2로 세서 한국어 상한이 약 140자다. 미션 기준(280자)만 맞출지, 실제 게시 기준까지 맞출지 프롬프트템플릿.md에 설계 근거로 적는다.
- **모델은 글자 수를 잘 못 센다:** 프롬프트의 목표값을 기준보다 여유 있게 잡고 Code 노드로 검증한다.
- **이미지 API 비용:** Google 개발자 포럼 답변 기준으로 Gemini API 이미지 생성은 무료 티어에서 쓸 수 없다. OpenAI 이미지 생성도 크레딧 결제가 필요하다. 소액 결제를 준비한다.
- **n8n 인증 형식 (실제로 막힌 곳, 2026-11-28):** Header Auth의 Value를 잘못 넣어 두 번 실패했다 (n8n 실행 #9, #10).
  - Codyssey: Anthropic 방식 키를 넣어 `401 Authentication is required`가 났다. OpenAI 방식 키로 바꿔 해결했다.
  - Notion: `Bearer `를 빼서 `401 Authorization header must use the format "Bearer <token>"`가 났다.
  - Gemini는 헤더 이름이 `x-goog-api-key`이고, `Bearer` 없이 키만 넣는다.
- **노션 이미지 저장:** 이미지 생성 API가 주는 링크는 만료되는 임시 링크일 수 있다.
  - Notion File Upload API 3단계(업로드 객체 생성 → 파일 전송 → 페이지·블록에 첨부)로 저장한다.
  - n8n 기본 Notion 노드에 업로드 기능이 없으면 HTTP Request 노드로 호출한다.
  - 업로드 후 1시간 안에 첨부해야 하므로 한 번의 실행 안에서 끝낸다.
- **리포트 파일 이름:** 본문은 `코랩세션리포트.md`, 폴더 예시는 `세미나리포트.md`로 되어 있다. 본문 기준을 따르고, 애매하면 운영진에게 확인한다.
- **질문지 원본:** `트랙C_소셜콘텐츠자동생성_2026-10-20.md`는 세션 전에 따로 받아 둔다.

## 6. 참고 자료: 릴스 프롬프트 카드 6장

### 가져올 패턴

- **역할은 한 줄:** "너는 ~야" 뒤에 바로 과업
- **바뀌는 값은 [ ] 자리로:** n8n에서는 `{{ $json.topic }}` 같은 폼 값 표현식이 된다. 폼 필드 이름은 영어로 둔다.
- **조건은 셀 수 있게:** 안 개수, 줄 수, 강조어 개수처럼 숫자로 정해야 Code 노드로 검증할 수 있다.
- **하지 말 것을 명시:** "인사·자기소개 없이" 등 금지 조건을 따로 적는다.
- **바꿀 점:** 카드는 결과를 표로 받지만, 워크플로우는 다음 노드가 읽을 수 있게 JSON으로 받는다.

### 카드별 활용

| 카드 | 활용 |
| --- | --- |
| 03 Hook Writer | 인스타그램 캡션 첫 줄, X 첫 문장 |
| 05 Cover Copywriter | 블로그 제목 (얻는 것을 분명하게, 강조어 하나) |
| 04 Script Editor | "순서는 그대로" 원칙만 빌려 플랫폼별 구조를 고정한다. 남의 대본을 그대로 두고 내용만 바꾸면 복사 금지에 걸릴 수 있어 구조만 참고한다. |
| 01, 02 | 실제 인스타그램 데이터가 필요해서 계정·수치를 지어낼 위험이 크다. 워크플로우에 쓰지 않는다. |
| 06 Voice Consultant | 음성 산출물이 없어 해당 없음 |

- 카드 자체도 타인의 콘텐츠다. 프롬프트템플릿.md에 출처를 밝히고 문장은 직접 쓴다.

## 7. 프롬프트 초안 (v0)

```text
[인스타그램]
너는 인스타그램 캡션 작가야
주제는 [주제], 보는 사람은 [대상], 톤은 [톤]이야
- 첫 줄: "더 보기"를 누르기 전에 읽히는 한 문장. 인사·자기소개 없이 결과나 궁금증으로 시작
- 본문: 3~5줄, 한 줄에 한 가지 내용
- 마지막 줄: 저장이나 댓글을 부르는 한 문장
- 해시태그: 정확히 10개, 넓은 태그와 좁은 태그를 섞어서
- 확인할 수 없는 통계·수치는 쓰지 마
출력은 JSON만: {"caption": "...", "hashtags": ["#...", ...], "hook_type": "첫 줄에 쓴 훅 기법"}
```

```text
[블로그]
너는 블로그 칼럼 작가야
주제는 [주제], 보는 사람은 [대상], 톤은 [톤]이야
- 제목: 읽으면 얻는 것을 분명하게, 강조어는 딱 하나
- 도입: 2~3문장, 인사 없이 독자가 겪는 문제로 시작
- 본문: 소제목 3개, 소제목마다 2~3문단
- 마무리: 핵심을 한 문단으로 정리
- 전체 공백 포함 800~1,200자
- 확인할 수 없는 통계·수치·출처는 쓰지 마
출력은 JSON만: {"title": "...", "body": "마크다운 본문, 소제목은 ##"}
```

```text
[X]
너는 X(트위터) 카피라이터야
주제는 [주제], 톤은 [톤]이야
- 첫 문장: 인사 없이 결론이나 긴장감으로 시작
- 핵심 2~3개를 한 문장씩
- 해시태그 2개 이하
- 해시태그 포함 전체 120자 이내
- 확인할 수 없는 통계·수치는 쓰지 마
출력은 JSON만: {"post": "...", "hook_type": "첫 문장에 쓴 훅 기법"}
```

```text
[이미지 프롬프트]
너는 SNS 대표 이미지 아트디렉터야
주제 [주제]로 이미지 생성 AI에 넣을 영어 프롬프트 1개를 써줘
- 장면 하나, 주인공 하나
- 스타일, 색감, 구도를 각각 한 줄로
- 이미지 안에 글자, 로고, 실존 브랜드, 캐릭터를 넣지 않기
- 정사각형(1:1)
출력은 JSON만: {"image_prompt": "..."}
```

**수치 근거**

- 블로그 800~1,200자: 미션 기준 500자에 여유를 둔 값
- X 120자: 한국어 상한 약 140자에 여유를 둔 값
- `hook_type`: 게시글에는 쓰지 않고 노션에만 저장해 A/B 비교 근거로 사용
